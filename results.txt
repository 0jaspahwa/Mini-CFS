  B. fairness under churn: 4 never-ending tasks, one per core,
     plus 40 short tasks dumped on core 0 every 8000 ticks. the 4
     are identical, so they should end with identical CPU time.

policy                min ms     max ms     max/min   jain       done     migrations  worst wait  drift ms    
--------------------------------------------------------------------------------------------------------------
no stealing           35264      800000     22.69     0.7717     200      0           800         764740      
steal when idle       35264      800000     22.69     0.7717     200      0           800         764740      
steal on imbalance    415904     416096     1.00      1.0000     960      936         18          288         
imbalance, raw vrt    416000     416000     1.00      1.0000     960      1008        18          8           

     idle-only never fires here - every core always has its own
     task, so none is ever empty, and core 0 drowns anyway. same
     score as no stealing at all.
     raw vruntime is NOT broken in this test: a balancer that keeps
     counts level also keeps clocks close, so re-timing has nothing
     to fix. that's a real result, and it's why C exists.

  C. one migration, across cores whose clocks drifted apart.
     core A ran 1 task for 10k ticks, core B ran 20. then one task
     moves from B to A. watch A's resident task.

raw vruntime    38000         26.2            73.8            9500            

     same steal, same task. only difference: one line placing the
